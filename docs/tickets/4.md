## What to build

Si una respuesta posterior introduce una posible urgencia, la conversación deja de comparar precios y muestra la interrupción. Los casos independientes no comparten información o resultados.

Demo para confirmar participación en un reto: Panamá, español, USD, datos ficticios y consultas ambulatorias. La especificación completa del padre rige este ticket. Las pruebas se realizan en la API pública de conversación y estimación, frontera confirmada por el usuario.

## Acceptance criteria

- [ ] Evaluar posible urgencia en la descripción inicial y en cada respuesta posterior; no esperar a completar las cinco preguntas.
- [ ] Al interrumpir, no solicitar herramientas económicas ni generar nuevas comparaciones; retirar precios anteriores del caso de la interfaz.
- [ ] Mostrar un mensaje de búsqueda de atención sin afirmar diagnóstico ni que la demo descarta emergencias.
- [ ] Mantener la interrupción del caso aunque el modelo proponga una comparación; reiniciar explícitamente permite un caso independiente.
- [ ] Al cambiar o reiniciar caso, limpiar contexto, contador y resultados; impedir mezcla entre conversaciones concurrentes y respuestas tardías.
- [ ] Probar desde la API una urgencia inicial, sobrevenida antes del límite y después de una comparación; comprobar ausencia de precios y aislamiento entre casos.
- [ ] Verificar en navegador la retirada de importes visibles y documentar que las reglas son ilustrativas, no un triaje clínico validado.
