## What to build

El agente pide únicamente información faltante y termina las preguntas cuando comprende el caso; si agota cinco preguntas, explica la incertidumbre y ofrece comparar una consulta inicial.

Demo para confirmar participación en un reto: Panamá, español, USD, datos ficticios y consultas ambulatorias. La especificación completa del padre rige este ticket. Las pruebas se realizan en la API pública de conversación y estimación, frontera confirmada por el usuario.

## Acceptance criteria

- [ ] Contabilizar y hacer cumplir fuera del modelo un máximo de cinco preguntas de seguimiento por caso; no contar selección de plan ni descripción inicial.
- [ ] Cada pregunta solicita un dato o aclaración; no eludir el límite agrupando varias preguntas ni repetir datos ya aportados.
- [ ] Si tiene información suficiente a la tercera pregunta o antes, consultar las herramientas y mostrar comparación sin seguir preguntando.
- [ ] Si tras cinco preguntas falta información, explicar qué permanece incierto y ofrecer comparar una consulta inicial adecuada a edad y contexto, sin afirmar especialidad definitiva.
- [ ] No inventar edad, embarazo ni contexto indispensable que no se haya aportado; explicar la limitación si impide orientar.
- [ ] Mostrar historial transitorio, pregunta actual y transición a comparación en la interfaz; mantener la prioridad del bloqueo por posible urgencia.
- [ ] Probar en la API recorridos de parada temprana, cinco preguntas, intento de sexta pregunta y falta de contexto; usar resultados controlados de QVAC sin simular las herramientas reales.
